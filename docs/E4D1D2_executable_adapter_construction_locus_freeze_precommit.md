# E4D1D2 — executable adapter construction locus freeze

E4D1D1 froze 218 top-level assignment bindings and proved that all 17 frozen scientific/helper functions remain provenance-identical to their 2022 authorities. It also established three family-specific compatibility modes.

Before writing executable adapter code, one further static boundary is required: not every hard-coded member/path/year literal occurs in a top-level assignment. Some occur inside unguarded executable statements. D2 inventories those exact loci and freezes the 2019 container-member mapping before adapter source exists.

D2 does not execute or import any frozen 2022 method and does not open any 2019 semantic data row.

SCF member mapping is purely structural: each of the three 2019 SCF archives must expose exactly one DTA member, which is bound to the corresponding Summary, Full, or replicate role.

CPS member mapping is equally strict: the public and replicate archives must each expose exactly one DAT member for the relevant source role. Ambiguity blocks rather than triggering a guess.

ACS remains governed by the already validated 2019 version bridge; D2 only inventories the static field-access surface needed by the future ingestion layer.

A successful D2 authorizes only D2A, which may write the actual adapter source against this frozen locus registry. Coordinate values remain closed.
